=====================================================================
APPLICATION OVERVIEW
=====================================================================
GithubOrgClient lets a user type a GitHub organization name, fetch that organization's
public repositories from the official GitHub REST API (https://api.github.com), and browse
them in a list. Tapping a repository opens a details screen that fetches and shows extended
information about that single repository (full description, forks, watchers, open issues,
and — if the repo is a fork — the parent repository's full name).

The app uses:
- MVVM: ViewModel + LiveData hold and expose UI state; Fragments/Activity only observe and render.
- Navigation Component: single-Activity app, two Fragments connected by a nav graph.
- Retrofit + OkHttp: typed HTTP client for the GitHub REST API.
- Android View System (XML layouts), no Compose.
- No local database; no backend other than GitHub's public API (unauthenticated requests).

=====================================================================
FUNCTIONAL REQUIREMENTS
=====================================================================
Screen 1 — Repository List (RepoListFragment):
- EditText for organization name input.
- "Search" Button that triggers the network call for GET /orgs/{org}/repos.
- Centered, indeterminate circular ProgressBar shown only while the request is in flight.
- RecyclerView showing the returned repositories.
  - Each item shows: repository name (TextView) and description (TextView, maxLines="3",
    ellipsize="end").
  - If a repository's description is null/empty, show the literal text "No description message".
- Error / empty handling:
  - If the network call fails (HTTP error, IOException, timeout) OR returns an empty list,
    clear the currently displayed list and show a Toast with the exact text:
    "No repos found for organization <orgName>" where <orgName> is exactly what the user typed.
- Tapping a list item navigates (via Navigation Component, passing the org name and repo name
  as Safe-Args-free Bundle arguments) to Screen 2.

Screen 2 — Repository Details (RepoDetailsFragment):
- Centered, indeterminate circular ProgressBar shown only while the request is in flight.
- Calls GET /repos/{org}/{repo} to fetch full repository details independently of Screen 1's data.
- ScrollView containing TextViews for:
  - Name
  - Full description (no line limit / no truncation)
  - Forks count
  - Watchers (subscribers) count
  - Open issues count
  - Parent repository full name — its row/TextView is only visible when "fork" == true for
    this repository; otherwise its container View is set to GONE.
- Toolbar with an Up (back) navigation button wired through the Navigation Component
  (NavigationUI.setupActionBarWithNavController + fragment shows Up as enabled).

=====================================================================
STRUCTURE ELEMENT RELATIONS
=====================================================================
- MainActivity hosts a single NavHostFragment driven by nav_graph.xml; it owns the Toolbar
  and wires it to the NavController via NavigationUI so Up navigation on RepoDetailsFragment
  works automatically.
- RepoListFragment creates/obtains RepoListViewModel (ViewModelProvider scoped to the
  Fragment). The ViewModel calls GitHubRepository.listOrgRepos(org, callback), which calls
  GitHubApiService (built by RetrofitClient) on a background thread via Retrofit's async
  enqueue(). Results are posted back to LiveData<Resource<List<Repository>>> which the
  Fragment observes to toggle the ProgressBar, submit data to RepoAdapter, or show the Toast.
- RepoAdapter binds Repository items into item_repository.xml views and exposes an
  OnItemClickListener; RepoListFragment implements this to call
  NavController.navigate(R.id.action_repoList_to_repoDetails, bundleOf(...)).
- RepoDetailsFragment reads orgName/repoName from getArguments(), obtains
  RepoDetailsViewModel, which calls GitHubRepository.getRepoDetails(org, repo, callback) and
  exposes LiveData<Resource<Repository>>. The Fragment observes it to populate all TextViews
  and to show/hide row_parent based on Repository.isFork().
- GitHubRepository is the single seam between ViewModels and Retrofit; ViewModels never call
  GitHubApiService directly. This keeps ViewModels testable and layering MVVM-clean.
- Resource<T> standardizes LOADING/SUCCESS/ERROR across both screens so both Fragments use
  identical logic to toggle ProgressBar visibility and surface error state.

=====================================================================
KEY METHODS PER ELEMENT
=====================================================================
GitHubApiService
- @GET("orgs/{org}/repos") Call<List<Repository>> listOrgRepos(@Path("org") String org);
- @GET("repos/{owner}/{repo}") Call<Repository> getRepo(@Path("owner") String owner, @Path("repo") String repo);

RetrofitClient
- static Retrofit getInstance() — lazily builds a singleton Retrofit with base URL
  https://api.github.com/, GsonConverterFactory, and an OkHttpClient with reasonable
  connect/read timeouts (e.g. 15s) and an HttpLoggingInterceptor in debug builds.

GitHubRepository
- void listOrgRepos(String org, RepoCallback<List<Repository>> callback) — invokes
  GitHubApiService.listOrgRepos(org).enqueue(...), maps HTTP failure / non-2xx / null-or-empty
  body to callback.onError(...), otherwise callback.onSuccess(list).
- void getRepoDetails(String org, String repo, RepoCallback<Repository> callback) — same
  pattern for the single-repository call.

RepoListViewModel
- LiveData<Resource<List<Repository>>> getRepos() — exposed immutable LiveData backed by a
  MutableLiveData.
- void searchOrg(String orgName) — sets state to LOADING, calls
  GitHubRepository.listOrgRepos, posts SUCCESS(list) or ERROR(orgName) to the LiveData;
  ERROR also carries orgName so the Fragment can format the Toast text exactly as required.

RepoDetailsViewModel
- LiveData<Resource<Repository>> getRepoDetails()
- void loadRepoDetails(String org, String repo) — LOADING → GitHubRepository.getRepoDetails
  → SUCCESS/ERROR.

RepoAdapter
- void submitList(List<Repository> repos) — replaces internal data set and calls
  notifyDataSetChanged() (or DiffUtil, either is acceptable, DiffUtil preferred).
- onBindViewHolder — sets name text; sets description text to
  "No description message" when Repository.getDescription() is null or blank, else the
  actual description (TextView already has maxLines="3" + ellipsize="end" in XML).

RepoListFragment
- onViewCreated — sets up RecyclerView (LinearLayoutManager + RepoAdapter), sets
  btn_search.OnClickListener to read et_org_name text and call viewModel.searchOrg(text).
- observeState — single observer on viewModel.getRepos() switching on Resource.status to
  toggle pb_loading visibility, call adapter.submitList(...), or clear the adapter's list and
  show Toast.makeText(requireContext(), "No repos found for organization " + orgName,
  Toast.LENGTH_SHORT).show().

RepoDetailsFragment
- onCreate — reads String orgName / repoName from getArguments(); calls
  setHasOptionsMenu(true) if a menu is used.
- onViewCreated — calls viewModel.loadRepoDetails(orgName, repoName); observes LiveData to
  populate TextViews and toggle row_parent's visibility via
  row_parent.setVisibility(repo.isFork() ? View.VISIBLE : View.GONE).

Repository (model)
- Fields (Gson @SerializedName where the JSON key differs from the Java field name):
  name, full_name, description, fork (boolean), forks_count, watchers_count/subscribers_count,
  open_issues_count, parent (nullable, itself a Repository — only present when fork == true and
  the single-repo endpoint is used; GSON will simply leave it null for the list endpoint).
- Getters for every field; isFork() alongside getFork() or via @SerializedName("fork").
